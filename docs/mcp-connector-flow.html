Claude connector: URL se jawab tak

Aap connector settings me ek URL paste karte ho. Uske baad Claude 46 steps chalata hai — pehle pata karta hai ki server protected hai, phir khud ko register karta hai, consent leta hai, token banwata hai, aur phir tools call karta hai. Har step ka asli HTTP aur wo file jo usko handle karti hai neeche hai. Play dabao.

Ye illustration nahi hai. Host api.imkumawatmanoj.com asli hai, tool get_profile asli hai, DCR ka body wahi hai jo real Claude Desktop ne bheja, aur file paths repo ke asli paths hain. End-to-end verified — Claude ka apna unattended token refresh bhi.

Jo abhi HS256 pe hai, aur jo abhi bana hi nahi

    

      Trace me sab kuch asli hai — jisme wo cheezein bhi hain jo aadhi hain. Doc me
      jhooth likhne se koi fayda nahi.
    

    

      

        
jwks_uri nahi hai

        
Tokens HS256 se sign hote hain — shared secret. AS aur RS ek hi process hain to chalta hai. Par koi doosra service token verify karna chahe to usko secret dena padega, jo usko token banane ki power bhi de deta hai. RS256 + JWKS isi ko theek karta hai; deferred hai.

      

      

        
scopes_supported do jagah alag

        
AS metadata poora SCOPES catalog deta hai (8 scopes), RS metadata sirf read_profile. Dono sach hain — AS "main kya jaanta hoon", RS "is resource pe kya kaam ka hai". Par ek client dono padh ke confuse ho sakta hai.

      

      

        
Grant revoke ka endpoint nahi hai

        
Poori machinery bani hai: FK cascade, gid claim, Redis marker. Jo nahi hai wo DELETE /v1/oauth/grants/:id hai. Matlab aaj user apna connected app hata nahi sakta — step 45 dikhata hai ki banne par kya hoga.

      

      

        
Per-user mcpLimiter nahi hai

        
Global IP limiter lagta hai, par spec ka "rate limit tool invocations" ek hi user ke against aadha-poora hai. app.ts me TODO(rate limit) pada hai.

      

      

        
Code replay rokte hain, detect nahi karte

        
GETDEL se dusri redemption fail hoti hai — par OAuth 2.1 ye bhi kehta hai ki replay hue code se pehle jo tokens diye the unko revoke karo. Uske liye tombstone chahiye. Jaan-boojh ke nahi banaya.

      

      

        
Confidential client support nahi

        
token_endpoint_auth_methods_supported: ["none"]. Table aur CHECK constraint client_secret_hash ke liye ready hain, par /token par secret verify karne wala code nahi hai. Public client + PKCE hi poora flow hai.

      

    

  


  

    
Teen bug jo sirf asli Claude se test karne pe mile

    

      Teeno ne local curl test paas kiya tha. Teeno asli client ke saath fail hue.
      Isliye "real wala hi test karenge" ek preference nahi, requirement hai.
    

    

      

        
1 · CSP form-action ne 302 chup-chaap roka

        
form-action sirf ye nahi decide karta ki form kahan post kare — wo ye bhi decide karta hai ki us POST ka response kahan redirect kar sake. App-wide policy 'self' thi, to consent ke baad client ko jaane wala 302 block ho gaya. Server log me 302, DB me grant bana hua, aur user ko wahi screen. Error sirf browser console me. Fix: sendAuthPage() per-response CSP bhejta hai jisme ek already-verified redirect origin naamzad hai.

      

      

        
2 · audienceConfig() me MCP branch hi nahi tha

        
Pehli authenticated MCP request pe verifyToken(token, resourceUri) ne Unknown JWT audience throw kiya → 500. Discovery aur OAuth poora chal gaya tha; ye uske baad toota. Bina asli token ke ye code path chalta hi nahi.

      

      

        
3 · Consent screen ne narrowed scope dikhaya, requested grant kiya

        
GET decision.grantable render karta tha, POST pending.scopes grant karta tha — jo client ne maanga tha. Matlab user ne jo approve kiya, wo usse zyada mil sakta tha. Fix: narrowed set pending record me likha jaata hai (attachUser), to screen aur grant kabhi alag nahi ho sakte.

      

    

  


  

    
Jahan log phaste hain

    
Ye saat cheezein trace me marked hain — build karte waqt in pe rukna.

    

      

        
1 · aud check chhod dena

        
Sabse common bug. Kisi doosre server ke liye bana valid token aapke server pe chal jaayega — "confused deputy". resource param (RFC 8707) isi liye hai.

      

      

        
2 · Token passthrough

        
MCP spec me explicitly mana hai — upstream ka token aage forward karna, ya doosre audience ka token accept karna. Har hop apna token.

      

      

        
3 · Consent skip karna

        
Third-party client hai. User ko dikhna chahiye kaunse scopes diye jaa rahe hain. Silent grant = security bug, feature nahi.

      

      

        
4 · Tool description ko doc samajhna

        
Wo prompt hai. Model usi se decide karta hai. "Kab call karna hai" likho — sirf "kya karta hai" likhne se tool trigger hi nahi hoga.

      

      

        
5 · Arguments ko trust karna

        
arguments model ka output hai — untrusted. Zod parse + per-tool scope check + tenant filter. Auth ≠ authz.

      

      

        
6 · Bada tool result

        
Result seedha model ke context me jaata hai. 500 rows bhejna context jalana hai. Paginate karo, summary do, cursor rakho.

      

      

        
7 · Ek hi mcp scope

        
Sab tools ek scope ke peeche = all-or-nothing. Per-tool scopes do (read_profile vs write_profile) taaki user read-only de sake. defineTool me scope per-tool declare hota hai, aur SUPPORTED_SCOPES usi se derive hota hai.
